## Platform

web

## Stack

Open decision. The approved visual concept will be built under `website/`; the implementation framework is intentionally deferred until then.

## Users

- Confirmed audience constraint: the website should appeal to children and people who are curious about programming.
- Inferred primary audience: Dutch-speaking beginners and students who find English-first programming intimidating.

## Product Purpose

The repository describes N-Lang as “Een manier om programmeren beschikbaar te maken voor niet Engels sprekenden.” The referenced PWS context describes a Dutch programming language intended to make programming concepts approachable, with a small language potentially translated to Java or another target. The exact language scope is still open.

## Positioning

Inferred position: a Dutch-first entry point to programming that lets beginners learn programming ideas in familiar language while still engaging with real code structure.

## Operating Context

N-Lang is being developed as a practical component of a Dutch school research project (PWS) about designing and implementing a programming language. The first website surface should explain the idea quickly and make the concept feel inviting to try.

## Capabilities and Constraints

- This request covers visual proposals for the future website, not the language implementation.
- The website must use a dark visual foundation and colorful accents.
- The tone should be appealing to children without becoming childish, while remaining credible to adults and technical readers.
- There must be no intro animation before the website is available. Purposeful in-page motion is welcome.
- The provided N-Lang logo is an existing asset and should remain recognizable.
- Product details, syntax, compiler target, and interactive demo behavior remain open decisions.

## Brand Commitments

- Product name: N-Lang.
- Existing identity asset: orange tulip-like mark on a very dark ground.
- The user referenced Mobbin examples with editorial hero composition, product previews, vivid gradients, and playful educational illustration as inspiration, not as a request to copy them.

## Product Principles

- Familiar language should lower the barrier to starting.
- Show programming as something people can make, not only something they must study.
- Keep the underlying technical substance visible and honest.
- Make the first interaction inviting without hiding the learning goal.
- Use delight to support comprehension and exploration.

## Accessibility & Inclusion

The dark theme must maintain readable contrast, clear hierarchy, and obvious interactive states for beginners and younger users. Exact accessibility targets remain to be confirmed during implementation.
